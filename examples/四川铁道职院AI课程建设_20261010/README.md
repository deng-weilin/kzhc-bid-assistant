# 金样例：四川铁道职业学院 AI 课程建设（竞争性磋商）

## 这是什么

本 skill 的**回归基线**。输入是一份 46 页、7 章的真实政府采购磋商文件（项目编号 `N5100012026002044`，采购包预算 650,000.00 元）。

**样例中不含客户原件**（招标文件 docx/pdf 未随包分发），只保留抽取指纹、带行号正文与全部产出，以避免把客户资料固化进 skill。复跑时把原件放回 `input/` 即可。

## 为什么值得当基线

它同时踩中了本 skill 设计时要解决的每一类真实问题：

| 现象 | 在本样例中的体现 |
| --- | --- |
| 要求跨章分布 | 工作内容在第三章，分值在第五章，约束在第二/四/七章 |
| 分值以池存在 | 50 条符号条款共同构成 1 个 48 分池，而非逐条分值 |
| 符号承载分值 | ▲12 / ●10 / █3 / 无符号25；另有 ★ 实质性条款 27 条 |
| 文件自身有缺陷 | 第三章"八、虚拟仿真资源运行要求"序号 (2) 漏标 ● 符号（`SYMBOL_GAP`） |
| 符号范围污染 | 第 624 行评分规则描述句一行内引用 ★▲●█，导致源文本符号计数各比实际条款多 1（`STAR_SCOPE`） |
| 多格式冲突 | 明确规定"以 pdf 为准"（`FORMAT_SOURCE_CONFLICT`） |
| 资料为零 | 阴性对照：全部缺失，不得出现任何已覆盖 |

| 文件 | 说明 |

## 回归复跑

```bash
# 1. 抽取（需先放回原件 input/磋商文件.docx 与 .pdf）
python scripts/extract_tender.py \
  --input input/磋商文件.docx --input input/磋商文件.pdf --output-dir output

# 2. 校验三份产出（源文件须与产出同目录，R15/R16 才会真正执行）
python scripts/validate.py --stage S1 --input examples/四川铁道职院AI课程建设_20261010
python scripts/validate.py --stage S2 --input examples/四川铁道职院AI课程建设_20261010
python scripts/validate.py --stage S3 --input examples/四川铁道职院AI课程建设_20261010

# 3. 校验器自身元验证
python scripts/self_test.py
```

## 基线结果（改动校验器或脚本后必须复现）

| 阶段 | 结果 |
| --- | --- |
| S1 | 契约 ✓ ｜ R1—R8 + R15 + R16 全通过 ｜ 120 条需求 ｜ 分值池 `12×1.5 + 10×0.5 + 3×5.0 + 25×0.4 = 48.0` 闭合 |
| S1 | 符号台账：源文本 58 处符号（★30 / ▲13 / █4 / ●11）全部登记；★ 维度 `COVERED 27 / EXEMPT 3` |
| S2 | 契约 ✓ ｜ `covered=0 / partial=0 / missing=96 / expired=0 / review=24` ｜ `gate_missing=48` |
| S3 | 契约 ✓ ｜ R12—R14 全通过 ｜ `plan_status=BLOCKED` |
| self_test | **20/20**（3 条正常路径 + 17 类错误注入逐条被拒） |

**S2 的 `covered`/`partial`/`expired` 三项为 0 是硬断言。** 首次运行时曾出现 `partial=7`，原因是空模板 profile 里的空业绩条目被误判为"已有业绩"——修复后才达标。这类退化如果再次发生，说明零幻觉约束破了。

## v0.2.0 修正记录（相对 v0.1.x）

本样例在 v0.1.x 时期带着以下缺陷发布，且当时 **8 项业务规则全部为绿**。缺陷是改用"源文本 ↔ 产出"对账后才发现的：

| 缺陷 | 内容 | 现状 |
| --- | --- | --- |
| **D1 ★ 实质性条款漏拆** | 源文本 ★ 共 30 处（其中 27 处构成实质性条款），v0.1.x 的 `requirements` 中仅 1 条落位 | 已补 17 条新需求 + 为 10 条已有需求补挂 ★，现落位 27 条，台账另记 3 处 `EXEMPT` |
| **D2 已拆条目丢符号** | 服务期限/服务地点/验收交付/支付方式/付款进度/违约责任/响应有效期/不接受联合体/2.4.6 编制签章加密 共 9 条本带 ★，`severity_symbol` 为空 | 已全部补挂 |
| **D3 locator 溯源断裂** | locator 指向另一份抽取文件 `tender-analysis/tender_raw.txt`（★(3) 在其第 499 行），该文件未随包分发；包内 raw 中同一条在第 387 行。旧 README 曾声称"locator 全部指向它"，**该说法不实** | 全部 locator 已按 `quote` 前 80 字在包内 raw 精确重锚（103/103 命中，0 失败） |
| **D4 校验器结构性盲区** | R5 只比对产出内部三个字段（`actual` / `symbol_reconciliation` / `scoring_pool`），产出整体缩水时三者同步缩水，仍然一致 | 新增 R15（源↔产出逐行台账）与 R16（locator 可回指）。**这两条规则现在会拦下 v0.1.x 的产出**——见 `../_regression_v0.1.0_should_fail/` |
| **D5 issue 内含未经核实的行号** | v0.1.x 的 `STAR_SCOPE` 与 `STAR_COVERAGE_GAP` 两条 issue 称"第 567/584/588/592/596/600/605 行为实质性 ★ 条款"——**这些行在文件中是"最后报价/澄清/复核/推荐成交候选供应商"，一个 ★ 都没有** | 已删除该错误引用；`SYMBOL_GAP` 的 `source_ref` 由"docx 第557行"改为动态定位得到的"docx 第445行 / PDF 第22页"。**行号一律从原文定位，不凭记忆写** |
| **D6 交付数量语义错判** | 表1 的裸数量（"20个""15个""1套""1本"）被判为 `None`；"60个（每套不低于30秒）"因括号内的单件约束被判为 `AT_LEAST` | 检测器改为先剥离括号内约束、再匹配主数量，且 `EXACT` 只认"数量短语收尾"句式。修复 14 条；同时排除了 4 处正文数字误判（"每提供1个业绩""30个工作日内付40%"等） |

**教训一：v0.1.x 的 8 条规则全绿，却漏掉了绝大部分实质性要求。只做"产出内部自洽"的校验，对覆盖度没有证据。**
**教训二：凡是能"从原文读出来"的东西（行号、数量语义），就必须从原文读，不能凭记忆写。D5 与 D6 是同一类错误的两次出现。**
